# Project documentation workflow

## Ownership and intake
- Dineth owns interpretations, hypotheses, decisions, and conclusions.
- Treat pasted reading notes as documentation input when he asks to document/save them. Preserve original wording in a dated source record only when approved for public storage.
- A pasted note is not by itself approval for public publication. Prepare a faithful draft in the conversation or a private location, then publish when requested or under explicit standing publication authorization.
- Public repositories expose raw files and drafts even when Quarto does not render them.
- Read existing notes and progress before editing. Do not overwrite others' changes.

## Minimal useful bookkeeping
- Use one stable path per paper/topic: notes/short-slug.qmd. Use templates/reading.md as a guide, omitting irrelevant empty headings.
- Record source URL, paper version/date and publication status when verified, creation/modification dates, open questions, and possible experiments where present.
- Keep publication date, note date, and experiment run date distinct.
- Separate published findings, Dineth's interpretations, assistant suggestions, and personally reproduced results. Never invent missing content.
- Update progress.qmd only when a meaningful decision, completed milestone, or next action changes.
- Keep one original record per submitted note; append later corrections without silently rewriting history.
- Cite original sources; never claim current relevance or a research gap without checking newer work.

## Delivery
- Validate with quarto render before committing where available.
- Use descriptive commits. Review changes before pushing. No force pushes.
- For requested publication, push the approved changes and verify the deployment and affected live page. If tools cannot verify, report the precise pending check.
- Report note link, short change summary, and any missing information. Never claim successful upload or deployment without evidence.
- No paid services, API runs, or training without explaining expected cost first.
